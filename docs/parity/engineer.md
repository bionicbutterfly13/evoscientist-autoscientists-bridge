# Parity audit: Engineer Agent / Experiment Tree Search (paper §3.4, §4.5, App. D, RQ2)

Paper: arXiv 2603.08127 (EvoScientist). Code: [EvoScientist/EvoScientist](https://github.com/EvoScientist/EvoScientist/tree/e2eef14) at v0.3.8 (HEAD e2eef14). Read-only.

## Two evidence sources, kept apart

- **Repo** (`EvoScientist/...`): the v0.3.8 package. It contains no engineer-agent, experiment-tree-search, stage, budget, best-node or execution-report code. Anything engineer-like there is prompt text in `EvoScientist/prompts.py` and `EvoScientist/subagents/*.yaml`.
- **External skill** (`~/.evoscientist/skills/...`): the 4-stage pipeline, the attempt budgets and the M_E retrieval live only in EvoSkills markdown skills (`experiment-pipeline`, `experiment-iterative-coder`, `evo-memory`). They are installed locally from EvoSkills commit `6d92ea5d` (see `~/.evoscientist/skills/.installed.yaml`). They are not in the repo and not installed by default: onboarding only recommends them (`EvoScientist/config/onboard/steps.py:1101-1106`). The repo prompt reaches them by name (`prompts.py:60-66`, `prompts.py:112-114`). Everything in them is natural-language instruction to the LLM, so the best status they can earn is **Prompt-only (ext. skill)**.

Paths are abbreviated in the table below: `EP` = `~/.evoscientist/skills/experiment-pipeline`, `IC` = `~/.evoscientist/skills/experiment-iterative-coder`, `EM` = `~/.evoscientist/skills/evo-memory`.

## 2. Missing or divergent, ranked (by impact on reproducing paper results)

1. **No execution-success-rate harness (row 24).** RQ2's Figure 2 numbers cannot be regenerated. Nothing in the repo or tests defines a trial, counts executable runs per stage, or compares before and after ESE.
2. **No coded experiment tree search, budget enforcement or best-node selection (rows 8-13).** The paper's Eq.7-8 mechanism (bounded attempts N_E^s, argmax over execution records, best node carried forward) exists only as markdown instructions in an optional external skill. Run-to-run behavior, attempt counts and stage transitions therefore depend on the LLM's compliance, and the "rule-based" no-executable-code failure (row 19) cannot fire deterministically.
3. **M_E retrieval is not embedding-based, and k_E is not 1 in code (rows 4-7).** The repo uses lexical IDF ranking with an LLM-chosen limit (default 8), and the skill uses LLM judgment over a markdown file. Which strategies reach the engineer can differ from the paper's cosine top-1, which drives the ESE gains claimed in RQ2.
4. **The four-stage structure is not built into the repo (row 9).** The repo's own workflow prompt says stages are "flexible, not rigid" (`prompts.py:92`). Paper-faithful staging requires installing EvoSkills and the LLM choosing `experiment-pipeline`, so a default install will not run the paper's pipeline.
5. **Model mismatch (row 21).** The paper uses Claude-4.5-Haiku for code generation. The repo's code-agent uses the single main model (default `claude-sonnet-5-5`) with no separate code-model setting, so success rates are not comparable as shipped.
6. **Execution history and report W are underspecified (rows 15-17).** Trajectory logs store change summaries, not the code itself, and the final report template has no run-status or failure-diagnosis fields. ESE and IVE inputs therefore differ from H_E^s and W in Eq.9-10 and Fig.11.
7. **No 4-worker parallelism (row 20).** Parallel fan-out is optional and its size is chosen by the LLM. This affects wall-clock time and how many attempts get explored within the budget.
8. **Skill-only additions change behavior (rows 26-27).** Gate thresholds, budget-adjustment rules and planner reflection are not in the paper and can end stages earlier or later than the paper's N_E-bounded search.

## 3. Searched but uncertain

- **EvoSkills version used for the paper.** The local skills are at EvoSkills commit `6d92ea5d` (paper-review at `7dde27cd`). I could not establish which skill version, if any, produced the paper's results, or whether the paper ran a different internal codebase with real tree-search code. The skill text calls itself a "follow[ing] of the Experiment Tree Search design from the EvoScientist paper" (`EP/SKILL.md:13`), which suggests it is a later prompt-level reimplementation.
- **Stage 1 meaning.** The paper's "initial implementation" is not defined further. The skill reads it as "reproduce baseline within 2%" (`EP/SKILL.md:65-71`). I could not determine whether the paper's Stage 1 success means "runs without error" (consistent with an *execution* success rate) or "matches reported metrics".
- **Remote EvoSkills HEAD.** I audited only the locally installed copy. The current upstream EvoSkills may differ, and I did not fetch it (read-only scope, no installs).
- **Top-1(E) semantics in Eq.8.** It is unclear whether ranking is by the primary metric or by run status. No code exists to disambiguate it.
- **`experiment-craft` skill** (the diagnosis step referenced by `EP/SKILL.md:167-181`) is installed but was not read in depth. It is prompt-only in any case.
